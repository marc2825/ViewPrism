# Security, privacy and rights inventory (2026-11-26)

This is an engineering inventory, **not legal advice**. License, name and publication decisions are
the owner's.

## Behaviour of the add-on

| Topic | Status |
|---|---|
| Network access | none (no sockets, HTTP, or URL opening); no `network` permission requested |
| External processes | none (`bpy.ops.wm.path_open` opens the output folder in the OS file manager on request) |
| Dynamic code | no `eval`/`exec`/`pickle`/`__import__`, no `sys.path` changes, no downloads, no auto-update |
| Dependencies | Python standard library (`zlib`, `struct`, `json`, `os`, `re`, `secrets`, `datetime`, `concurrent.futures`, …), NumPy bundled with Blender, Blender modules (`bpy`, `gpu`, `gpu_extras`, `mathutils`, `blf`). No wheels, no pip |
| File writes | only inside the folder the user chose; names validated (no separators, reserved Windows names, control characters); resolved path must stay inside the folder; temporary file in the same folder + `os.replace`; never overwrites unless "Exact Name + Overwrite" is chosen; nothing written into the add-on directory |
| File reads | none in the product (decoders exist for tests only) |
| Scene / .blend | read-only use of the evaluated depsgraph; settings on the WindowManager (not saved into .blend files); no datablocks created; no undo steps |
| Metadata JSON | contains Blender version, matrices, resolution, frame, object names (ID map), warnings, timings and file names. **No absolute paths, user names or .blend paths** (tested). Object names are user content and are written on purpose |
| Manifest permission | `files` only, with a one-sentence reason |

## Repository and CI

- GitHub Actions may use only GitHub-owned actions; the default workflow token is read-only and only the
  tag-triggered release job requests `contents: write` (draft release).
- CI downloads official Blender Linux builds from download.blender.org and verifies them against the
  published SHA-256 list (`.github/scripts/fetch_blender.sh`). This is CI tooling only; the add-on itself
  never downloads anything.
- Dependabot alerts, automated security fixes and weekly Actions updates are enabled. Secret scanning is
  not available for this private repository on the current plan.
- CI evidence is sanitised the same way as local evidence (`<HOME>`/`<USER>`).

## Code and asset origin

- All product and test code in `viewpass/`, `tests/`, `tools/` was written for this project in this
  branch. Competitors were studied from public pages and source **to describe approaches only**; no
  code or assets were copied (see `docs/COMPETITORS.md`).
- PNG and OpenEXR encoders/decoders were implemented from the public format specifications (PNG spec;
  OpenEXR file layout, ZIP predictor/reordering).
- The ZIP contains no images or other binary assets.
- README images (`docs/images/`) are generated by `tools/make_screenshots.py` from a procedural scene of
  Blender primitives (no Suzanne, no third-party assets). The UI screenshots show Blender's interface
  (GPL software) without the splash or the Blender logo. They are produced with an empty, isolated
  user directory so no recent-file names or paths appear.
- The development starter kit (`viewpass-dev/`) is the owner's input and is kept unchanged.

## License
