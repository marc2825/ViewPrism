## Behaviour of the add-on

| Topic | Status |
|---|---|
| Network access | none (no sockets, HTTP, or URL opening); no `network` permission requested |
| External processes | none (`bpy.ops.wm.path_open` opens the output folder in the OS file manager on request) |
| Dynamic code | no `eval`/`exec`/`pickle`/`__import__`, no `sys.path` changes, no downloads, no auto-update |
| Dependencies | Python standard library (`zlib`, `struct`, `json`, `os`, `re`, `secrets`, `datetime`, `concurrent.futures`, …), NumPy bundled with Blender, Blender modules (`bpy`, `gpu`, `gpu_extras`, `mathutils`, `blf`). No wheels, no pip |
| File writes | no-clobber publication via hard link (Windows: no-replace rename; elsewhere a safe failure if hard
links are unavailable), AUTO numbers reserved with an exclusive lock file; only inside the folder the user chose; names validated (no separators, reserved Windows names, control characters); resolved path must stay inside the folder; temporary file in the same folder + `os.replace`; never overwrites unless "Exact Name + Overwrite" is chosen; nothing written into the add-on directory |
| File reads | none in the product (decoders exist for tests only) |
| Scene / .blend | read-only use of the evaluated depsgraph; settings on the WindowManager (not saved into .blend files); no datablocks created; no undo steps |
| Metadata JSON | contains Blender version, matrices, resolution, frame, object names (ID map), warnings, timings and file names. **No absolute paths, user names or .blend paths** (tested). Failures are stored as error codes with fixed messages; free text is path-redacted. Object/camera names are written on purpose in *Full* mode; *Anonymized* mode replaces them (tested). Images, chosen file names and camera geometry can still reveal scene content |
| Manifest permission | `files` only, with a one-sentence reason |

## Repository and CI

- GitHub Actions may use only GitHub-owned actions, pinned to full commit SHAs (Dependabot updates the pin
  and the version comment). The default workflow token is read-only; checkouts do not persist it. Only
  the release *publish* job requests `contents: write`; it runs no repository code and only uploads the
  files the read-only build job produced, after re-verifying their checksums.
- Python tools in CI (NumPy, ruff) are installed from hashed requirement files (`ci/`, `--require-hashes`).
- CI downloads official Blender builds (Linux, Windows; macOS in the manual probe) from
  download.blender.org. Only the archive is cached. The official SHA-256 list is fetched fresh on every
  run, and the archive is verified against it before extraction; a mismatching cache entry is deleted
  (`.github/scripts/fetch_blender.sh`). gitleaks is downloaded with a pinned SHA-256. This is CI tooling
  only; the add-on itself never downloads anything.
- Secret scanning in CI (job "Secrets and privacy scan"): gitleaks over all refs with redacted output,
  proven by a freshly generated canary that it must detect, plus `tools/privacy_scan.py` over the tree
  and every reachable blob (reviewed historical findings in `tools/privacy_allowlist.txt`).
- GitHub settings: Dependabot alerts and security updates, secret scanning with push protection,
  private vulnerability reporting (see `SECURITY.md`) and CodeQL code scanning are enabled.
  *Non-provider patterns* and *validity checks* could not be enabled for this personal repository
  through the API (GitHub reports them as disabled); gitleaks and the repository scan cover generic
  patterns instead.
- CI evidence is sanitised the same way as local evidence (`<HOME>`/`<USER>`, including the Windows 8.3
  short form of the home directory) and scanned before a run can pass.

## Code and asset origin

- **Documented origin (not independently verified by a third party):** all product and test code in
  `viewprism/`, `tests/`, `tools/` was written for this project. Competitors were studied from public pages and source **to describe approaches only**; no
  code or assets were copied (see `docs/COMPETITORS.md`).
- PNG and OpenEXR encoders/decoders were implemented from the public format specifications (PNG spec;
  OpenEXR file layout, ZIP predictor/reordering).
- The ZIP contains no images or other binary assets.
- README images (`docs/images/`) are generated by `tools/make_screenshots.py` from a procedural scene of
  Blender primitives (no Suzanne, no third-party assets). The UI screenshots show Blender's interface
  (GPL software) without the splash or the Blender logo. They are produced with an empty, isolated
  user directory so no recent-file names or paths appear.
- The development starter kit (`viewpass-dev/`) is the owner's input. Its harness is kept unchanged;
  the development prompt and research brief were removed from the tree on 2026-11-26 (still in history).
- **Automated checks:** `tools/privacy_scan.py` scans the tree, the git history, the ZIP and the
  evidence for private data, credentials and PNG metadata. gitleaks scans the full history in CI.
  Neither proves provenance: they find leaks, not copied code.
