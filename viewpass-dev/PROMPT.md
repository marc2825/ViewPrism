# Claude Codeへの開発依頼：ViewPass / Viewport Pass Exporter

あなたは Blender GPU API、CG、Python、UI/UX、OSS公開、テスト設計に詳しいシニアエンジニアです。既存リポジトリ https://github.com/marc2825/Depth_Renderer を、軽量な Blender アドオン ViewPass（仮名）に発展させてください。最終報告は日本語、コード・UI・コミット・英語READMEは英語を基本とする。日本語READMEも用意する。

## ゴール
現在操作している3Dビューポートを起点に、カメラ作成・コンポジタ設定・レンダリング設定変更なしに、Depth / Normal / Object ID / Mask をプレビュー・一括書き出しできるローカル完結型ツールを作る。速さ・手軽さ・出力の正確さ・非破壊性を優先する。AI専用ツールにしない。

必読：`docs/SPEC.md`, `docs/TEST_CONTRACT.md`, `docs/RESEARCH_RELEASE.md`, `docs/MANUAL_QA.md` と `harness/` 全ファイル（このPROMPTのあるディレクトリからの相対パス）。

## 作業ルール
- 現在のブランチ、git status、コミット履歴、既存コードを調べ、変更・未コミットデータを保持。無断で reset/clean/rebase/force push しない。既存リポジトリの履歴を継承し、必要なら専用作業ブランチを切る。リモート変更、名称変更、公開、提出、push、ライセンス確定はユーザーの承認まで行わない。不要な個人パスは公開対象から除外し、履歴に残るものは別途報告（勝手に履歴改変しない）。
- 現状の README は空、旧実装は BGL 未import、旧式OpenGL、非三角形メッシュ、投影・正規化などに問題がある可能性。実際の状態を確認してから判断。旧描画コアに固執しない。
- Blender 4.5 LTS を初期最低候補とし、利用可能な安定版 5.x（最新安定版は公式で確認）も試験する。実測前に対応を宣言しない。GPU APIのみを利用（bgl/直接OpenGL/私的API禁止）。標準ライブラリとBlender同梱NumPyを優先し、pipの自動実行やネット通信を製品に含めない。
- 競合の調査は公開情報のみで行い、他人の実装・資産の無断コピー禁止。アクセス不能なら未確認とする。性能・独自性・ライセンスの根拠を記録。
- テスト専用の偽出力やハードコードは不可。GPU検証ハーネスは製品と同じ描画関数を呼ぶ。独立した期待値・閾値を弱めない。仕様変更は理由・比較・更新テストを記録する。
- ユーザー環境で Blender が起動できない場合は静的・純粋数値テストを進め、GPU未検証と明示。必要な実機コマンドを残す。失敗をskipやPASSに変換しない。

## 実行順序 / stage gates
### Phase 0 — 棚卸し・競合・技術検証
- 旧実装、履歴、権利関係、環境（OS、Blender実パス/版、GPUバックエンド）を棚卸し。
- 競合機能比較、既存標準機能との差、名称候補の重複調査。暫定名で開発可。
- 最小GPU PoCで頂点/フラグメントシェーダ、深度/法線/ID/マスク、透視/正投影、状態復元を実測。方式A: カスタムGPU幾何パスを第一候補、方式B: draw_view3d + depth readback、方式C: 通常レンダーパスは比較用のみ。代替方式を選ぶなら制約と理由を残す。
- `docs/decisions/0001-renderer.md` と `docs/COMPETITORS.md` 作成。実現性が低いパスは理由を明記してスコープ縮小可。

### Phase 1 — 描画コア
- ルートに `viewpass/` パッケージを構築（旧ファイルは整理）。独立ハーネス契約に沿い実装。ユーザー操作でも同じコアを通す。
- 評価済みdepsgraph、インスタンス、可視性、投影、法線変換、画素方向、背景、GPUリソース管理を明示。
- 最小Depth → Normal/ID/Maskへ。純粋数値テスト、登録テスト、GUI GPU テスト。背景テストだけでGPU合格としない。

### Phase 2 — 書き出し
- 数値配列とファイル保存を分離。解像度・範囲・反転・命名・衝突・上書き確認・エラー処理・メタデータ。PNG/EXRは実ファイル再読込で検証。16bit/32bitは実現できたものだけ提供する。
- 複数パス同一カメラ・同一可視条件・同一解像度。同一フレームから取得。プレビューと実データを混同しない。

### Phase 3 — UI / UX
- 3D View N-panel、パス選択、解像度、Depth範囲、Preview、Export Selected。最初はUIをシンプルに。
- Preview はまず手動更新。安全に成立してからオプションで自動更新（debounce、負荷制限、停止、例外時解放）。選択中のエリアを特定する。ファイルブラウザ遷移前に view を取得、失効時は明示エラー。
- 操作ステップ・速度・画像正確性の既存手段比較。クリップボードはWindowsの実画像コピーを検証できる場合のみ追加。

### Phase 4 — 品質・配布準備
- テストマトリクス、手動QA、性能測定、セキュリティ、権利関係、バージョン対応を記録。
- Blender Extension構造、manifest、build/validate/install/uninstallテスト。ライセンス候補GPL-3.0-or-later（権利とユーザー承認までは確定しない）。製品ZIPに開発ハーネスや私的情報を含めない。
- README英日、スクリーンショット（実出力）、制限、CHANGELOG、CONTRIBUTING、配布準備チェック。
- `docs/STATUS.md`: 実装済み/未実装、検証済み環境、テスト件数と生ログ参照、未解決問題、次に行うこと。公開/提出/名称変更はしない。

ユーザーへの確認が必要な破壊的/外部公開操作以外は自律的に進める。各phaseを小さくコミット可能な単位にし、テスト結果に応じて進める。合格ゲートを通らない段階を完了扱いしないが、独立して進められる作業は継続する。優先度は正確な描画＞非破壊性＞UI＞追加機能。最後に差別化が成立したか否かも批判的に評価する。
